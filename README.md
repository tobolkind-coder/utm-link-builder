# Инструкция по установке и настройке UTM Link Builder

> **Версия:** `v2` (актуальная).  
> **Ветка `main`** содержит предыдущую версию проекта.

Этот сервис предназначен для генерации маркетинговых ссылок. Данное руководство описывает требования к серверу, процесс установки и безопасности.

## 1. Требования к VPS
Для работы сервиса рекомендуется использовать VPS со следующими характеристиками:
- **CPU:** 1 core
- **RAM:** 1 GB (рекомендуется 2 GB)
- **Disk:** 10 GB SSD
- **OS:** Linux (Ubuntu 22.04/24.04 рекомендуется)
- **Software:** Docker, Docker Compose
- **DNS:** Заранее направьте A-запись вашего домена на IP-адрес VPS.
- **Firewall:** Откройте порты 80 (HTTP) и 443 (HTTPS).

## 2. Безопасность (ВАЖНО)
- **Смена пароля:** После первой установки обязательно войдите под `admin` / `admin123` и смените пароль администратора.
- **Порты:** По умолчанию база данных работает только на `127.0.0.1` (недоступна из интернета).
- **Секреты:** Используйте уникальные значения для `AUTH_SECRET` и `POSTGRES_PASSWORD`.
- **Rate-limiting входа:** После 5 неудачных попыток входа (по IP и по логину) доступ блокируется на 5 минут. Значения хранятся в таблице `Settings` (`loginAttemptsLimit`, `loginBlockDuration`); интерфейса для их изменения пока нет.
- **Определение IP:** Адрес клиента берётся из `X-Real-IP`, который проставляет Nginx. Присланный клиентом `X-Forwarded-For` перезаписывается на уровне прокси и не может использоваться для обхода блокировки.
- **Логи Docker:** Ограничены 10 MB на файл, хранится не более 3 файлов на контейнер — логи не забьют диск.
- **Healthcheck:** Для сервиса `web` настроена проверка доступности (`/api/health` каждые 30 секунд) — состояние видно в `docker compose ps`. Автоматического перезапуска по результату проверки Docker Compose не выполняет; падение самого процесса покрывается политикой `restart: unless-stopped`.
- **Продление SSL:** Certbot продлевает сертификат в общий том, Nginx раз в 6 часов перечитывает конфигурацию и подхватывает его. Доступ к Docker-сокету хоста контейнерам не выдаётся.
- **Node.js:** Используется Node.js 22 LTS (поддержка до апреля 2027).
- **Зависимости:** При сборке автоматически применяются overrides для устранения известных уязвимостей в транзитивных пакетах (postcss, sharp).

## 3. Установка (Автоматическая)

### Linux (через скрипт)

```bash
# Клонируйте репозиторий (ветка v2 — актуальная версия)
git clone -b v2 https://github.com/tobolkind-coder/utm-link-builder.git && cd utm-link-builder

# Запустите скрипт установки
sudo bash install.sh
```

**Что спросит скрипт:**
1. **Domain:** Введите ваш домен (например, `go.company.ru`). Этот домен будет использоваться как для сайта, так и для формирования коротких ссылок.
2. **Email for SSL:** Введите ваш email для получения уведомлений от Let's Encrypt (опционально).

**Результат:**
После завершения скрипт выведет адрес страницы входа, логин и пароль. 
**Важно:** Корень домена (`https://<ваш-домен>`) намеренно отдаёт 404 в целях безопасности. Страница входа имеет уникальный случайный адрес (например, `https://<ваш-домен>/auth-1234567890abcdef`), который скрипт выведет в конце установки. Вы можете изменить этот путь в разделе "Admin > Settings".

### Windows (через Docker Desktop)
1. Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/).
2. Запустите `install.bat`.

## 4. Резервное копирование базы данных

В проекте есть скрипт `scripts/backup.sh`, который создаёт дамп PostgreSQL и хранит последние 14 копий.

### Ручной запуск
```bash
sudo bash scripts/backup.sh
```
Дамп сохраняется в папку `backups/` в корне проекта.

### Автоматический ежедневный бэкап (через cron)
```bash
# Откройте crontab для редактирования
sudo crontab -e

# Добавьте строку для ежедневного запуска в 3:00 ночи:
0 3 * * * cd /path/to/utm-link-builder && bash scripts/backup.sh >> backups/cron.log 2>&1
```

**Рекомендация:** периодически копируйте дампы за пределы сервера (на другой хост, в облачное хранилище или на отдельный диск).

## 5. Обновление
Если вы используете git (в ветке `v2`):
```bash
git pull
sudo bash install.sh
```

Повторный запуск `install.sh` безопасен: существующие пароль базы и `AUTH_SECRET` считываются из текущего `.env` и сохраняются, предыдущая версия файла остаётся в `.env.bak`.

**Важно:** перед обновлением рекомендуется сделать бэкап базы данных:
```bash
sudo bash scripts/backup.sh
```

После обновления старые Docker-образы можно очистить командой:
```bash
docker image prune -f
```

## 6. Автоматическое обновление зависимостей (Dependabot)

Для репозитория на GitHub можно включить автоматические уведомления об уязвимостях и PR с обновлением пакетов:

1. Создайте файл `.github/dependabot.yml` в корне репозитория:
```yaml
version: 2
updates:
  - package-ecosystem: "npm"
    directory: "/"
    schedule:
      interval: "weekly"
  - package-ecosystem: "docker"
    directory: "/"
    schedule:
      interval: "weekly"
```
2. В настройках репозитория GitHub: Settings → Code security → включите "Dependabot alerts" и "Dependabot security updates".
3. Dependabot будет автоматически создавать PR с обновлением пакетов при выходе новых версий или при обнаружении уязвимостей.

## 7. Решение проблем
- **Как попасть в админку после установки:**
  Если вы пропустили URL, выполните:
  ```bash
  docker compose logs web | grep "Login page"
  ```
- **Сайт недоступен:** Убедитесь, что DNS-запись домена настроена верно и порты 80/443 открыты на VPS.
- **SSL ошибки:** Если SSL не заработал, выполните принудительный перевыпуск:
  ```bash
  sudo bash scripts/init-ssl.sh <ваш-домен> <ваш-email>
  ```
- **Сайт недоступен сразу после установки (404/SSL ошибки):**
  Часто это вызвано попаданием невидимых управляющих символов терминала (escape-последовательностей) в переменную домена при вводе в скрипте.
  **Диагностика:** Выполните `cat -A .env | grep SHORT_DOMAIN`. Если видите странные символы в начале строки (например `^[[...`), переустановите сервис. В текущей версии скрипта (install.sh) добавлена автоматическая очистка и валидация домена.
- **Ошибка `failed to solve: Internal: rpc error...` при сборке:**
  Если при сборке возникает эта ошибка, попробуйте временно отключить BuildKit:
  ```bash
  export DOCKER_BUILDKIT=0
  docker compose build
  docker compose up -d
  ```
  Если ошибка повторяется, создайте issue в репозитории.
- **Логи:** `docker compose logs -f web`
