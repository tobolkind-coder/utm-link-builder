# Acceptance Tests

Версия: 1.0

---

# Общие требования

Проект считается завершённым только после успешного прохождения всех тестов, описанных в данном документе.

Все проверки выполняются на полностью развернутом приложении через Docker Compose.

---

# 1. Запуск проекта

## Проверка

Запустить:

```bash
docker compose up -d
```

### Ожидаемый результат

- контейнеры успешно запускаются;
- приложение доступно в браузере;
- база данных доступна;
- ошибок запуска нет;
- миграции применены автоматически.

---

# 2. Авторизация

## Вход

Проверить вход существующего пользователя.

### Ожидаемый результат

- вход успешен;
- создается защищенная сессия;
- открывается главная страница.

---

## Неверный пароль

Ввести неправильный пароль.

### Ожидаемый результат

- вход запрещен;
- отображается понятное сообщение об ошибке;
- сессия не создается.

---

## Выход

Нажать кнопку "Выход".

### Ожидаемый результат

- сессия уничтожена;
- происходит переход на страницу входа;
- защищенные страницы становятся недоступны.

---

# 3. Генерация ссылок

## Простая ссылка

Ввести:

```
https://example.com
```

Выбрать только Source.

### Ожидаемый результат

создается ссылка

```
https://example.com?utm_source=...
```

создается короткая ссылка

короткая ссылка автоматически копируется в буфер обмена.

---

## URL без протокола

Ввести

```
example.com
```

### Ожидаемый результат

автоматически используется

```
https://example.com
```

---

## URL с GET-параметрами

Ввести

```
https://example.com?id=15
```

### Ожидаемый результат

UTM добавляются через

```
&
```

а не через

```
?
```

---

## Замена существующих UTM

Ввести

```
https://example.com?utm_source=old&utm_medium=test
```

### Ожидаемый результат

старые UTM удаляются

новые UTM создаются

дубли отсутствуют.

---

## Campaign

Проверить:

- только первая часть;
- только вторая часть;
- обе части;
- ни одной части.

Во всех случаях результат должен соответствовать требованиям документации.

---

## Content

Проверить:

- только дата;
- дата + текст.

Не должно появляться лишних символов "_".

---

# 4. Короткие ссылки

Создать новую ссылку.

Открыть короткий URL.

### Ожидаемый результат

сервер возвращает

HTTP 302

происходит переход на UTM-ссылку.

---

## Несуществующая ссылка

Открыть случайный shortCode.

### Ожидаемый результат

HTTP 404.

---

# 5. История

Создать несколько ссылок.

### Проверить

отображаются последние 15 записей;

новые записи находятся сверху;

отображаются только ссылки текущего пользователя.

---

## Кнопка "Копировать"

Нажать кнопку.

### Ожидаемый результат

короткая ссылка копируется;

отображается уведомление.

---

## Кнопка "Открыть"

### Ожидаемый результат

ссылка открывается в новой вкладке.

---

# 6. Пользователи

Создать нового пользователя.

### Проверить

- пользователь появляется в таблице;
- вход возможен;
- пароль работает.

---

## Изменение пользователя

Изменить имя.

### Ожидаемый результат

изменения сохраняются.

---

## Отключение

Отключить пользователя.

### Проверить

авторизация становится невозможной.

---

## Soft Delete

Удалить пользователя.

### Проверить

- пользователь исчезает из списка;
- записи в таблице Links сохраняются;
- авторизация невозможна.

---

# 7. Справочники

Добавить новый Source.

### Проверить

элемент появляется в списке.

---

Отключить Source.

### Проверить

обычные пользователи его больше не видят;

администратор продолжает видеть.

---

# 8. Настройки

Изменить:

- название сервиса;
- короткий домен.

### Проверить

изменения применяются без ошибок.

Создать новую ссылку.

### Проверить

используется новый короткий домен.

---

# 9. Интерфейс

Проверить:

- отсутствуют неработающие кнопки;
- отсутствуют пустые страницы;
- отсутствуют ошибки отображения;
- отсутствуют alert();
- отображаются Toast;
- отображаются Skeleton.

---

# 10. Производительность

Создать большое количество ссылок.

### Проверить

история по-прежнему показывает только последние 15 записей.

---

# 11. Безопасность

Попытаться открыть административные маршруты обычным пользователем.

### Ожидаемый результат

HTTP 403.

---

Попытаться выполнить административный API-запрос без авторизации.

### Ожидаемый результат

HTTP 401.

---

данные базы сохраняются.

# Финальная проверка

Проект считается готовым только при выполнении всех условий:

✅ Все тесты пройдены.

✅ Все функции работают согласно документации.

✅ Docker Compose запускается без ошибок.

✅ Авторизация работает.

✅ Генерация ссылок работает.

✅ Редирект HTTP 302 работает.

✅ История отображается корректно.

✅ Административная панель полностью функциональна.

✅ Отсутствуют TODO, FIX ME и mock-данные.
