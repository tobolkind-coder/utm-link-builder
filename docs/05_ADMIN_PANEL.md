# Admin Panel

Версия: 1.0

---

# Общая информация

Административная панель предназначена для управления пользователями, справочниками UTM и настройками сервиса.

Доступ к административной панели имеют только пользователи с ролью **Administrator**.

Попытка открыть административные страницы пользователем без соответствующих прав должна приводить к ошибке **403 Forbidden**.

Все проверки доступа выполняются на сервере.

---

# Структура административной панели

Административная панель состоит из трех разделов:

1. Пользователи
2. Справочники UTM
3. Настройки

Навигация может быть реализована в виде:

- бокового меню;
- вкладок.

Все разделы должны открываться без полной перезагрузки страницы.

---

# Раздел "Пользователи"

## Таблица пользователей

Отображаются только пользователи, у которых:

isDeleted = FALSE

По умолчанию сортировка:

createdAt DESC

Колонки:

- Логин
- Полное имя
- Роль
- Статус
- Дата создания
- Действия

---

## Создание пользователя

Кнопка

```
Создать пользователя
```

Открывает модальное окно.

### Поля

Логин *

Полное имя *

Пароль *

Подтверждение пароля *

Роль *

Активен

---

### Проверки

Логин:

- обязателен;
- уникален;
- от 3 до 100 символов;
- допускаются латинские буквы, цифры, `_`, `-` и `.`.

Пароль:

- минимум 8 символов;
- минимум одна буква;
- минимум одна цифра.

Пароль и подтверждение должны совпадать.

После успешного создания:

- закрыть модальное окно;
- обновить таблицу;
- показать Toast:

```
Пользователь успешно создан.
```

---

## Редактирование пользователя

Разрешается изменять:

- Полное имя;
- Роль;
- Статус (Активен / Неактивен).

Логин изменять запрещено.

Пароль изменяется отдельным действием.

---

## Смена пароля

Отдельная кнопка:

```
Сменить пароль
```

Открывает модальное окно.

Поля:

Новый пароль

Подтверждение

После успешного изменения:

```
Пароль успешно изменен.
```

---

## Отключение пользователя

Используется переключатель:

Активен

↓

Неактивен

Неактивный пользователь:

- не может войти в систему;
- все ранее созданные ссылки продолжают работать.

---

## Удаление пользователя

Используется **Soft Delete**.

При удалении:

- isDeleted = TRUE;
- isActive = FALSE;
- deletedAt = текущая дата и время.

Физическое удаление запрещено.

Все ссылки пользователя продолжают работать.

---

## Ограничения

Запрещается:

- удалить самого себя;
- удалить последнего администратора;
- изменить роль последнего администратора;
- отключить последнего администратора.

При нарушении этих правил сервер возвращает ошибку.

---

## Архив пользователей

Добавить переключатель:

```
Показывать архив
```

По умолчанию выключен.

При включении отображаются пользователи с:

isDeleted = TRUE

Для архивных пользователей:

- отображается статус "Удален";
- любые изменения запрещены;
- отображается только информация.

Архитектура должна позволять реализовать восстановление пользователя в будущем без изменения структуры базы данных.

---

Название

## Добавление элемента

Кнопка

```
Добавить
```

Открывает модальное окно.

Поля:

Название *

Порядок сортировки

Активен

После успешного сохранения:

- закрыть окно;
- обновить таблицу;
- показать уведомление.

---

## Редактирование

Разрешается изменить:

- название;
- порядок сортировки;
- активность.

---

## Удаление

Физическое удаление запрещено.

Вместо удаления используется изменение признака:

isActive

↓

FALSE

Неактивные элементы:

- не отображаются обычным пользователям;
- остаются в базе данных;
- могут быть повторно активированы.

---

## Сортировка

Используется поле:

sortOrder

Чем меньше значение,

тем выше элемент располагается в списке.

# Раздел "Настройки"

Раздел содержит глобальные настройки сервиса.

---

## Название сервиса

Тип:

Text Input

Используется:

- в Header;
- в заголовке страницы.

---

## Короткий домен

Тип:

Text Input

Пример:

```
go.company.ru
```

Допускается ввод:

```
go.company.ru
```

или

```
https://go.company.ru
```

При сохранении значение нормализуется.

Завершающий символ "/" хранить запрещено.

---

## Логотип

Загрузка файла.

Поддерживаемые форматы:

- SVG
- PNG

Максимальный размер:

2 MB

После сохранения новый логотип отображается без перезагрузки страницы.

---

## Favicon

Поддерживаемые форматы:

- ICO
- PNG

Максимальный размер:

1 MB

После сохранения favicon используется приложением.

---

## Сохранение

После успешного сохранения:

- показать Toast;
- обновить Header;
- не перезагружать страницу.

---

# Общие требования

Все формы должны иметь:

- клиентскую валидацию;
- серверную валидацию.

Кнопки должны блокироваться во время выполнения запросов.

Повторная отправка одного и того же действия не допускается.

---

# Интерфейс

Использовать единый стиль оформления.

Все модальные окна должны иметь:

- заголовок;
- описание действия;
- кнопку "Сохранить";
- кнопку "Отмена".

Закрытие окна по Esc допускается.

---

# Компоненты

Использовать единые переиспользуемые компоненты:

- DataTable
- Dialog
- ConfirmDialog
- Button
- Input
- Select
- Switch
- Tooltip
- Toast
- Skeleton

Не создавать отдельные реализации одинаковых элементов.

---

# Производительность

Не выполнять полную перезагрузку страницы после каждого действия.

После изменения данных обновлять только соответствующую таблицу или форму.

Использовать оптимистичное обновление интерфейса там, где это безопасно.

---

# Итог

Административная панель должна быть простой, понятной и безопасной.

Все изменения выполняются только пользователями с ролью Administrator.

Физическое удаление данных не используется.

Все действия сопровождаются понятной обратной связью и не требуют перезагрузки страницы.
