# Deployment

Версия: 1.0

---

# Общая информация

Проект должен разворачиваться на чистом Linux VPS с использованием Docker Compose.

Цель — максимально простое развертывание без установки Node.js, PostgreSQL и других зависимостей непосредственно на сервер.

После клонирования репозитория и настройки переменных окружения приложение должно запускаться одной командой.

---

# Требования к серверу

Минимальная конфигурация:

- 1 vCPU
- 1 GB RAM (рекомендуется 2 GB)
- 20 GB SSD
- Ubuntu 24.04 LTS (или совместимый Linux)

---

# Используемые сервисы

В составе Docker Compose должны запускаться:

- web (Next.js)
- postgres (PostgreSQL)

Дополнительные сервисы (Redis, MinIO и т.п.) не используются.

---

# Docker

Проект должен содержать:

Dockerfile

docker-compose.yml

.dockerignore

Все контейнеры должны запускаться без ручной настройки.

---

# Docker Compose

Команда

```bash
docker compose up -d
```

должна:

- собрать приложение;
- создать контейнеры;
- создать базу данных;
- применить миграции Prisma;
- выполнить импорт справочников (если таблицы пусты);
- запустить приложение.

После запуска сервис должен быть полностью готов к работе.

---

# Переменные окружения

Использовать файл:

.env

Минимальный набор параметров:

```text
DATABASE_URL=

AUTH_SECRET=

NEXTAUTH_URL=

SHORT_DOMAIN=

NODE_ENV=
```

Все значения должны читаться исключительно из переменных окружения.

Запрещается хранить конфиденциальные данные в исходном коде.

---

# Prisma

При запуске контейнера автоматически выполнить:

- prisma generate;
- prisma migrate deploy.

Если база данных уже актуальна, повторное выполнение не должно приводить к ошибкам.

---

# Импорт справочников

После применения миграций приложение должно проверить наличие данных в таблицах:

- UTM Source
- UTM Medium
- Campaign Part 1
- Campaign Part 2

Если таблицы пусты — выполнить импорт из файлов:

/docs/utm_source.txt

/docs/utm_medium.txt

/docs/utm_campaign_1.txt

/docs/utm_campaign_2.txt

Если данные уже существуют — импорт пропустить.

---

# Nginx и HTTPS

В проекте настроен Nginx с автоматическим получением SSL-сертификатов Let's Encrypt.

При запуске на Linux через `install.sh` автоматически настраивается HTTPS.

При ручной установке или на Windows необходимо настроить Reverse Proxy (например, Nginx) для терминирования HTTPS и проксирования запросов к контейнеру `web` на порт 3000.

---

# Порты

Контейнер приложения использует внутренний порт:

3000

Контейнер PostgreSQL:

5432

Порты должны быть настраиваемыми через docker-compose.yml.

---

# Хранение данных

Для PostgreSQL использовать Docker Volume.

Данные базы не должны теряться после перезапуска контейнеров.

---

# Обновление приложения

Стандартная процедура обновления:

```bash
git pull

docker compose build

docker compose up -d
```

После обновления автоматически применяются новые миграции.

---

# Логи

Использовать стандартные Docker Logs.

Приложение не должно создавать собственные лог-файлы.

Просмотр логов осуществляется командой:

```bash
docker compose logs -f
```

---

# Проверка готовности

После запуска должны выполняться следующие условия:

- приложение открывается в браузере;
- база данных доступна;
- авторизация работает;
- можно создать пользователя;
- можно создать короткую ссылку;
- редирект работает;
- история отображается.

---

# Итог
