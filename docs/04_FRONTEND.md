# Frontend

Версия: 1.0

---

# Общие требования

Frontend разрабатывается на:

- Next.js 15
- React
- TypeScript
- Tailwind CSS
- shadcn/ui

Основной приоритет — скорость работы, простота интерфейса и удобство использования.

Использовать только светлую тему.

Темная тема не требуется.

---

# Макет

Основным источником информации о внешнем виде является файл

/docs/ui.png

Необходимо максимально точно повторить:

- расположение элементов;
- размеры;
- цвета;
- шрифты;
- интервалы;
- размеры кнопок;
- размеры полей ввода;
- последовательность элементов.

Если макет противоречит документации, приоритет имеет документация.

Не изменять дизайн без необходимости.

---

# Общая структура страницы

Страница состоит из следующих блоков:

1. Header
2. Форма генерации ссылки
3. Блок результата
4. История последних ссылок

Все элементы располагаются вертикально.

---

# Header

Header всегда находится в верхней части страницы.

Содержит:

- логотип;
- название сервиса;
- имя текущего пользователя;
- кнопку "Выход".

Если пользователь имеет роль Administrator, дополнительно отображается кнопка:

"Администрирование"

При нажатии открывается административная панель.

---

# Форма генерации ссылки

Форма является главным элементом страницы.

Все поля располагаются согласно ui.png.

---

## URL

Тип:

Text Input

Placeholder

```
Вставьте ссылку
```

Поле обязательное.

Перед проверкой автоматически удалить пробелы в начале и конце строки.

При потере фокуса выполнить проверку URL.

Если отсутствует протокол

автоматически добавить

```
https://
```

Если URL некорректный

отобразить сообщение рядом с полем.

Не использовать alert().

---

## UTM Source

Тип

Select

Обязательное поле.

Данные загружаются с сервера.

Отображаются только активные записи.

Сортировка выполняется по sortOrder.

---

## UTM Medium

Тип

Select

Необязательное поле.

Работает аналогично Source.

---

## Campaign

Состоит из двух независимых Select.

Первый Select

Campaign Part 1

Второй Select

Campaign Part 2

Можно выбрать:

- только первый;
- только второй;
- оба;
- ни одного.

---

## Content

Состоит из двух элементов.

### Дата

Тип

Date Picker

По умолчанию

текущая дата.

На сервер отправляется в формате

YYYYMMDD

---

### Текст

Тип

Text Input

Placeholder

```
Введите значение
```

Поле необязательное.

---

# Кнопка "Создать ссылку"

Основная кнопка формы.

По умолчанию неактивна.

Активируется только после заполнения:

- URL;
- UTM Source.

При нажатии:

- выполняется проверка формы;
- отправляется запрос;
- кнопка становится недоступной;
- отображается индикатор загрузки.

Повторные нажатия игнорируются до завершения запроса.

---

# Блок результата

После успешного создания ссылки отображается отдельный блок.

Содержит:

Полная UTM-ссылка

Короткая ссылка

Кнопка

```
Копировать
```

Кнопка

```
Открыть
```

---

## Копирование

После успешного создания ссылки:

автоматически скопировать короткую ссылку в буфер обмена.

Использовать Clipboard API.

Если Clipboard API недоступен

использовать резервный механизм копирования.

После успешного копирования показать Toast.

```
Ссылка успешно скопирована.
```

---

# Поведение формы после создания

После успешного создания ссылки необходимо:

очистить

- URL;
- текстовую часть UTM Content.

сбросить

дату на текущую.

оставить выбранными

- UTM Source;
- UTM Medium;
- Campaign Part 1;
- Campaign Part 2.

автоматически вернуть фокус в поле URL.

Такое поведение действует только до обновления страницы.

Автосохранение между сессиями не требуется.

---

# История ссылок

Под формой отображается таблица.

Количество записей

15.

Показываются только ссылки текущего пользователя.

Сортировка

новые сверху.

---

## Колонки

Дата

Короткая ссылка

UTM-ссылка

Действия

---

### Дата

Формат

```
DD.MM.YYYY HH:mm
```

---

### Короткая ссылка

Отображается полностью.

Рядом находится кнопка копирования.

---

### UTM-ссылка

Если ссылка длиннее ширины таблицы

отображать сокращённо.

Например

```
https://site.ru/catalog?utm_...
```

При наведении отображать полный URL во всплывающей подсказке (Tooltip).

---

### Действия

Кнопка

```
Открыть
```

Открывает ссылку в новой вкладке.

---

# Обновление истории

После успешного создания ссылки история обновляется автоматически.

Перезагрузка страницы не требуется.

---

# Пустая история

Если пользователь ещё не создавал ссылки

отобразить сообщение

```
Вы еще не создали ни одной ссылки.
```

---

# Загрузка

Во время получения данных использовать Skeleton.

Не использовать бесконечные спиннеры вместо содержимого страницы.

---

# Toast уведомления

Использовать единый компонент уведомлений.

Показывать сообщения:

- ссылка успешно создана;
- ссылка скопирована;
- ошибка создания ссылки;
- ошибка копирования;
- настройки сохранены;
- пользователь создан;
- пользователь изменён;
- пользователь отключён.

---

# Валидация

Все ошибки отображать непосредственно рядом с соответствующим полем.

Не использовать alert().

Не использовать confirm().

---

# Горячие клавиши

Если форма валидна

клавиша

Enter

эквивалентна нажатию кнопки

"Создать ссылку".

Навигация по форме должна корректно работать с использованием клавиши Tab.

---

# Доступность

Все элементы формы должны иметь label.

Все кнопки должны иметь aria-label.

Интерфейс должен быть полностью доступен для управления с клавиатуры.

---

# Адаптивность

Основной сценарий использования — Desktop.

На планшетах интерфейс должен корректно масштабироваться.

На мобильных устройствах допускается вертикальное расположение элементов.

Функциональность должна сохраняться полностью.

---

# Работа с API

Не выполнять HTTP-запросы непосредственно внутри компонентов.

Использовать отдельный слой API.

Все ошибки API должны обрабатываться централизованно.

---

# Компоненты

Использовать переиспользуемые компоненты.

Например:

- Button
- Input
- Select
- DatePicker
- Toast
- Dialog
- Tooltip
- Table
- Skeleton

Не дублировать код.

---

# Итог

Frontend должен максимально соответствовать предоставленному макету, быть простым, быстрым и удобным.

Все действия пользователя должны сопровождаться понятной обратной связью.

Никакие элементы интерфейса не должны существовать без реализованной функциональности.
