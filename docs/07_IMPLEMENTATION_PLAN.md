# Implementation Plan

Версия: 1.0

---

# Общие требования

Разработка должна выполняться последовательно.

Переход к следующему этапу допускается только после полного завершения предыдущего.

Запрещается оставлять незавершённые функции, временные решения и заглушки.

---

# Этап 1. Создание проекта

Создать проект на базе:

- Next.js 15
- TypeScript
- Tailwind CSS
- shadcn/ui
- Prisma
- PostgreSQL

Настроить структуру каталогов проекта.

Создать Dockerfile.

Создать docker-compose.yml.

Создать .env.example.

---

# Этап 2. Настройка базы данных

Создать schema.prisma.

Создать все модели базы данных.

Настроить связи.

Создать миграции.

Настроить автоматическое применение миграций.

---

# Этап 3. Авторизация

Реализовать:

- страницу входа;
- проверку логина и пароля;
- создание защищённой сессии;
- выход из системы;
- проверку роли пользователя;
- защиту маршрутов.

После завершения этапа пользователь должен иметь возможность войти в систему.

---

# Этап 4. Импорт справочников

Реализовать автоматический импорт данных из файлов:

- utm_source.txt
- utm_medium.txt
- utm_campaign_1.txt
- utm_campaign_2.txt

Импорт выполняется только при пустых таблицах.

Повторный импорт не создаёт дубликатов.

---

# Этап 5. Генерация ссылок

Реализовать:

- форму генерации;
- серверную валидацию;
- удаление существующих UTM-параметров;
- добавление новых UTM;
- генерацию короткого кода;
- сохранение ссылки в базе данных;
- автоматическое копирование короткой ссылки.

После завершения этапа должна работать генерация ссылок.

---

# Этап 6. История ссылок

Реализовать:

- получение последних 15 ссылок пользователя;
- отображение истории;
- копирование короткой ссылки;
- открытие ссылки в новой вкладке;
- автоматическое обновление истории после создания новой ссылки.

---

# Этап 7. Редирект

Реализовать маршрут:

/{shortCode}

При открытии короткой ссылки:

- выполнить поиск записи;
- вернуть HTTP 302 Redirect;
- при отсутствии записи вернуть HTTP 404.

---

# Этап 8. Административная панель

Реализовать:

- список пользователей;
- создание пользователя;
- редактирование пользователя;
- смену пароля;
- Soft Delete пользователей;
- управление справочниками;
- управление настройками.

Все административные маршруты должны быть доступны только Administrator.

---

# Этап 9. Пользовательский интерфейс

Привести внешний вид приложения в соответствие с макетом:

/docs/ui.png

Проверить:

- расположение элементов;
- размеры;
- интервалы;
- состояния загрузки;
- Toast-уведомления;
- Skeleton-компоненты.

---

# Этап 10. Docker

Проверить:

- сборку контейнеров;
- запуск приложения;
- запуск PostgreSQL;
- применение миграций;
- импорт справочников;
- запуск приложения одной командой.

---

# Этап 11. Финальная проверка

Проверить:

- все API;
- авторизацию;
- генерацию ссылок;
- редирект;
- административную панель;
- настройки;
- Docker Compose.

Исправить найденные ошибки.

---

# Критерии завершения проекта

Проект считается завершённым только при выполнении всех условий:

- приложение успешно собирается;
- отсутствуют ошибки TypeScript;
- отсутствуют ошибки ESLint;
- отсутствуют TODO;
- отсутствуют FIX ME;
- отсутствуют mock-данные;
- все функции работают согласно документации;
- проект запускается через Docker Compose;
- база данных создаётся автоматически;
- миграции применяются автоматически;
- импорт справочников выполняется автоматически;
- авторизация работает;
- генерация ссылок работает;
- короткие ссылки работают;
- история отображается корректно;
- административная панель полностью функциональна.

---

# Приоритеты реализации

При возникновении спорных ситуаций соблюдать следующий порядок приоритетов:

1. Корректность бизнес-логики.
2. Безопасность.
3. Соответствие документации.
4. Производительность.
5. Удобство интерфейса.
6. Внешний вид.

---

# Запрещается

Во время реализации запрещается:

- изменять требования документации без явной необходимости;
- заменять обязательные функции упрощёнными аналогами;
- исключать этапы реализации;
- использовать временные решения вместо полноценной реализации.

---

# Итог

Результатом выполнения данного плана должен стать полностью готовый к эксплуатации веб-сервис, соответствующий всем требованиям документации проекта.
