# UTM Link Builder

## Техническое задание

Версия: 1.0

---

# 1. Общая информация

## 1.1 Назначение проекта

Разработать внутренний корпоративный веб-сервис для создания маркетинговых ссылок с UTM-метками и автоматической генерацией короткой ссылки на собственном домене компании.

Сервис предназначен исключительно для сотрудников компании и не является публичным.

Все пользователи создаются администратором. Самостоятельная регистрация отсутствует.

---

# 1.2 Основные возможности

Сервис должен предоставлять следующий функционал:

- авторизация пользователей;
- генерация UTM-ссылок;
- автоматическое удаление существующих UTM-параметров;
- корректная обработка URL с существующими GET-параметрами;
- генерация короткой ссылки;
- автоматическое копирование короткой ссылки в буфер обмена;
- просмотр последних созданных ссылок;
- управление пользователями;
- управление справочниками UTM;
- управление настройками сервиса;
- развёртывание через Docker Compose.

---

# 1.3 Цель разработки

Получить полностью готовый к эксплуатации внутренний сервис, который можно развернуть на любом недорогом VPS без доработок.

Проект не должен содержать демонстрационного функционала, временных решений, заглушек или незавершённых модулей.

# 5. Авторизация

Самостоятельная регистрация отсутствует.

Создавать пользователей может только администратор.

Авторизация выполняется по логину и паролю.

Пароли должны храниться исключительно в виде bcrypt hash.

После успешного входа пользователь получает защищённую HTTP Only Cookie.

Cookie должна иметь следующие параметры:

- HttpOnly;
- SameSite=Lax;
- Secure в production.

После выхода пользователя сессия должна уничтожаться.

# 6. Роли пользователей

## Administrator

Полный доступ ко всем разделам системы.

Может:

- создавать пользователей;
- изменять пользователей;
- отключать пользователей;
- управлять справочниками;
- изменять настройки;
- просматривать все административные разделы.

Может:

- копировать ссылки;
- открывать созданные ссылки.

Пользователь не должен иметь доступ к административной панели.

Все проверки ролей должны выполняться на сервере.

---

# 9. Правила формирования ссылки

Обязательные поля:

- URL;
- UTM Source.

Все остальные поля являются необязательными.

Перед созданием ссылки сервер обязан проверить корректность введённых данных.

---

## Проверка URL

Если пользователь вводит

site.ru

необходимо автоматически преобразовать значение в

https://site.ru

Перед проверкой автоматически удалить пробелы в начале и конце строки.

Если введённый URL невозможно корректно преобразовать, создание ссылки запрещается.

Пользователь должен получить понятное сообщение об ошибке.

---

## Работа с существующими GET-параметрами

При формировании итогового URL необходимо использовать стандартный класс URL.

Запрещается самостоятельно объединять строки.

Если URL уже содержит GET-параметры, новые UTM должны добавляться через символ "&".

Например:

Исходный URL:

https://site.ru/catalog?id=15

Результат:

https://site.ru/catalog?id=15&utm_source=google

Если GET-параметров нет, использовать символ "?".

---

# 10. Формирование UTM-параметров

Перед добавлением новых UTM-параметров сервер обязан удалить из URL все существующие параметры:

- utm_source
- utm_medium
- utm_campaign
- utm_content
- utm_term

Если перечисленные параметры отсутствуют, никаких действий выполнять не требуется.

Удаление и добавление параметров должно выполняться средствами стандартного класса `URL`.

---

## UTM Source

Источник трафика.

Тип поля:

Select.

Значения загружаются из базы данных.

Пользователь может выбрать только одно значение.

Поле является обязательным.

---

## UTM Medium

Тип трафика.

Тип поля:

Select.

Значения загружаются из базы данных.

Поле необязательное.

Если значение не выбрано, параметр `utm_medium` в ссылку не добавляется.

---

## UTM Campaign

UTM Campaign состоит из двух отдельных выпадающих списков.

Campaign Part 1

Campaign Part 2

Итоговое значение формируется следующим образом.

Если выбраны обе части:

campaignPart1_campaignPart2

Например:

spring_sale

Если выбрана только первая часть:

spring

Если выбрана только вторая часть:

sale

Если обе части пустые — параметр utm_campaign не создаётся.

Не допускается создание двойных символов "_" или символа "_" в начале либо конце значения.

---

## UTM Content

UTM Content состоит из двух частей.

Первая часть:

Дата.

Тип:

Date Picker.

По умолчанию используется текущая дата.

Перед сохранением дата должна быть преобразована в формат:

YYYYMMDD

Например:

20260723

Вторая часть:

Текстовое поле.

Необязательное.

Итоговое значение формируется следующим образом.

Если текст заполнен:

YYYYMMDD_text

Например:

20260723_banner

Если текст отсутствует:

20260723

Не допускается создание лишнего символа "_".

---

# 11. Генерация короткой ссылки

После формирования итогового URL сервер должен создать короткую ссылку.

Алгоритм работы.

1. Сформировать итоговую UTM-ссылку.

2. Сгенерировать случайный короткий код длиной от 6 до 8 символов.

Допускается использовать:

- латинские буквы;
- цифры.

Регистр учитывать.

Например:

A7HdK9

Перед сохранением необходимо проверить уникальность короткого кода.

Если код уже существует, необходимо повторить генерацию.

После получения уникального значения сохранить запись в базе данных.

---

## Формирование короткой ссылки

Короткая ссылка состоит из:

короткий домен

+

/

+

shortCode

Например:

https://go.company.ru/A7HdK9

Короткий домен хранится в настройках системы и может быть изменён администратором.

---

# 12. Редирект

При открытии короткой ссылки сервер должен:

1. Найти запись по shortCode.

2. Если запись отсутствует — вернуть HTTP 404.

3. Если запись найдена — вернуть HTTP Redirect 302 на сохранённую UTM-ссылку.

Редирект должен выполняться средствами HTTP.

Использование JavaScript Redirect запрещено.

---

# 13. История ссылок

После открытия главной страницы пользователь должен видеть последние 15 созданных им ссылок.

История сортируется по дате создания в порядке убывания.

Каждая запись должна содержать:

- дату создания;
- короткую ссылку;
- итоговую UTM-ссылку;
- кнопку открытия;
- кнопку копирования.

После создания новой ссылки история должна обновляться автоматически без перезагрузки страницы.

---

# 14. Поведение интерфейса

Кнопка "Создать ссылку" должна быть активна только после заполнения обязательных полей:

- URL;
- UTM Source.

При выполнении запроса:

- кнопка блокируется;
- отображается индикатор загрузки;
- повторные нажатия игнорируются.

После успешного создания ссылки:

- автоматически скопировать короткую ссылку в буфер обмена;
- показать уведомление об успешном создании;
- обновить историю ссылок;
- вернуть фокус в поле URL;
- очистить поле URL;
- очистить текстовую часть UTM Content;
- установить текущую дату в поле даты;
- сохранить выбранные значения UTM Source, UTM Medium, Campaign Part 1 и Campaign Part 2.

Сохранение выбранных значений действует только до перезагрузки страницы.

---

# 15. Политика хранения данных

Проект должен максимально сохранять данные.

Физическое удаление пользователей запрещено.

Использовать Soft Delete.

При удалении пользователя:

- установить isDeleted = TRUE;
- установить isActive = FALSE;
- заполнить deletedAt.

Все ссылки пользователя должны сохраняться.

Для справочников UTM физическое удаление также запрещено.

Каждый элемент имеет признак активности.

Неактивные элементы:

- остаются в базе данных;
- не отображаются обычным пользователям;
- могут быть повторно активированы администратором.

---
