# Database

Версия: 1.0

---

# Общая информация

В качестве базы данных использовать PostgreSQL.

Работа с базой данных осуществляется исключительно через Prisma ORM.

Все первичные ключи должны использовать UUID.

Использование автоинкрементных идентификаторов не допускается.

Все даты хранить в UTC.

---

# Общие правила

Для всех таблиц использовать:

- UUID Primary Key;
- createdAt;
- updatedAt.

Все связи должны быть реализованы средствами Prisma.

Запрещается использовать Raw SQL без необходимости.

Все остальные справочники не имеют внешних ключей.

Во время создания ссылки значения из справочников копируются в таблицу Links как текст.

Это гарантирует сохранность истории даже после изменения или отключения элементов справочников.

---

# Soft Delete

Используется только для пользователей.

При удалении:

isDeleted = TRUE

isActive = FALSE

deletedAt = текущая дата.

Физическое удаление пользователей запрещено.

---

# Деактивация справочников

Для всех UTM-справочников используется только поле

isActive.

Физическое удаление элементов запрещено.

Неактивные записи:

- остаются в базе;
- не отображаются пользователям;
- доступны администратору;
- могут быть повторно активированы.

---

# Импорт справочников

При первом запуске приложения необходимо проверить наличие данных в таблицах:

UtmSource

UtmMedium

UtmCampaignPart1

UtmCampaignPart2

Если таблица пуста, выполнить импорт данных из файлов:

/docs/utm_source.txt

/docs/utm_medium.txt

/docs/utm_campaign_1.txt

/docs/utm_campaign_2.txt

Каждая строка файла соответствует одной записи.

Порядок строк определяет значение sortOrder.

Повторный импорт не должен создавать дубликаты.

---

# Миграции

Все изменения структуры базы данных должны выполняться через Prisma Migrations.

Приложение не должно запускаться с неактуальной схемой базы данных.

При запуске через Docker Compose миграции должны применяться автоматически.

---

# Производительность

Использовать индексы для всех часто используемых полей.

Не выполнять выборку всех записей таблицы Links.

История пользователя всегда ограничивается последними 15 записями.

Использовать LIMIT на уровне базы данных.

---

# Резервное копирование

Структура базы данных должна позволять выполнять стандартное резервное копирование PostgreSQL без дополнительных действий.

Восстановление резервной копии не должно требовать ручной корректировки данных.

---

# Итог

Схема базы данных должна быть нормализована, обеспечивать ссылочную целостность, быть готовой к расширению и не требовать изменения структуры при добавлении новых пользователей, UTM-значений или ссылок.
